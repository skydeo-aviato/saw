Point it at the accepted issue — shape starts on the bare issue, in the cycle, before any project
exists. The issue body is chart-the-map's "loose idea", and the destination is grilled first. If
charting surfaces no fog, stop: no map, no project — the issue gets built as it stands. When fog
survives, "create the map" *is* Promotion (§6.1): the project is created with the settled
destination, and the issue moves in as the chart-the-map decision ticket — never a fresh one.

Pick the next ticket by the six buckets — §6.1 "Picking the next ticket".

Resolve a decision ticket with the reasoning, not just the verdict — the resolution comment carries
the alternatives considered and why each fell (§6.5).
